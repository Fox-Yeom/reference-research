# 보드 개편 가기획안 (초안 · 2026-10-15)

대상: `scripts/board.mjs`(카테고리 보드 + 라이브러리 홈), 필요한 만큼의 데이터 구조(`store.mjs`, `report.mjs`, `SKILL.md`).
상태: 검토 완료(2026-10-15, 추천안 채택) → **1단계 구현됨**(아래 §6). 2·3단계는 `ROADMAP.md`에 등록. 실제 라이브러리(`~/references`)는 읽기만 했고 바꾸지 않았다.

## 0. 진단 — 지금 무엇이 불편한가 (수치)

측정: 실제 라이브러리 18개 조사, 가장 큰 보드 `acne-skincare-products-kr`을 1440px 너비로 렌더링.

| 항목 | 값 | 뜻 |
|---|---|---|
| 보드 전체 높이 | **73,000px** (약 80화면) | 끝까지 읽을 수 없다 |
| 섹션별 높이 | 레퍼런스 30,570 (42%) · 출처 18,653 (26%) · 발견 9,893 · 패턴 8,960 · 요약 3,112 · 조사 기록 932 | 길이의 68%가 레퍼런스·출처 목록 |
| 캡처 없는 레퍼런스 | 이 보드 272개 중 **231개** · 라이브러리 전체 1,323개 중 975개 | 격자에서 빈 "글 출처 ↗" 타일로 그려진다 → 레퍼런스 섹션의 대부분이 빈 칸 |
| 조사 목적(goal) | `runs.jsonl`에만 있음(19회, 평균 108자). `collection.json`의 goal은 18개 모두 없음 | 헤더에는 개수 통계만 보이고, 목적은 요약 본문 안 같은 글자 크기의 문단 |
| 발견(claim) | 408개 · 평균 122자 · 최대 289자 · 150자 초과 116개(28%) · **subject 없음 153개(38%)** | 제목 없는 긴 문장이 같은 크기로 나열 |
| 발견의 조사 회차 | 408개 모두 `run`과 `events` 보유 | 데이터는 있는데 보드는 '조사 기록' 표에서만 회차를 쓴다 |
| 노트 | 평균 107자, 최대 6,223자. SKILL §5가 정한 구조(구조·카피·비주얼·UI 패턴·차용·피할 점)를 굵은 라벨로만 구분 | 뷰어 정보 패널에서 한 덩어리로 보인다 |
| 조사 간 공유 | 95개 레퍼런스가 2개 이상 조사에 속함 | 헤더에서는 보이지 않고 카드 정보 패널에서만 |
| 용어 | research 도메인에서도 "179개 제품" | 실제는 브랜드·발행처·논문 |

사용자가 말한 세 가지 불편의 원인:
1. **길어지면 보기 불편** → 레퍼런스·출처를 전부 펼침 + 빈 타일.
2. **조사한 이유를 찾기 어려움** → goal이 헤더에 없음, 요약·결론·근거·메타가 같은 위계.
3. **AI 조사와의 연결점이 없음** → ID(S#/C#/R#)는 있지만 "이걸 Claude에게 어떻게 넘기나"가 화면에 없음.

## 1. 설계 원칙

1. **위에서 아래로 "왜 → 결론 → 근거 → 원자료".** 아래로 갈수록 길어도 된다. 위는 한 화면에 끝난다.
2. **글자 위계는 세 단계만.** 결론(크고 굵게) · 근거(보통) · 메타(작고 흐리게). 색은 의미(역할·근거 세기·종류)에만 쓴다. 무채색 금지(DECISIONS 2026-10-02)는 유지.
3. **보이는 모든 것은 Claude에게 다시 넘길 수 있는 ID를 가진다.** S#·C#·R#·축 id. 복사 한 번이면 다음 조사의 입력이 된다.
4. **기본은 접고, 열면 전부.** 숨기지 않는다. 처음 보이는 양만 줄인다.
